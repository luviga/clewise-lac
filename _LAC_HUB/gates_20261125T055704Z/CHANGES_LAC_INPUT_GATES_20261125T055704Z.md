# CHANGES of LAC_INPUT_GATES (stamp 20261125T055704Z)

Feasibility checks for every compiled model input, built, proven on known defects and run on main, with no solve.
Nothing was solved; `glpsol --check` (translation and generation only) was the one solver call.

## Commit 1: the check suite

- `gates/__init__.py`, `gates/__main__.py`: the package and its entry point. `py -I gates --point <b1|final|results>`
  runs it from the repository root in isolated mode (isolated mode cannot import a package with `-m` from the
  working folder); `py -m gates` works too.
- `gates/gmpl.py`: reader of the GMPL files the solver reads. Parameter index sets come from the model file; data
  files are read with their declared defaults in every form the A2, B1 and Stage 3 scripts write (lists, slices,
  tables), recording duplicate keys, repeated blocks and elements missing from their sets.
- `gates/view.py`: one region of one data file with the bounds the model's constraints imply (reachable capacity
  through residual capacity, investments within operational life and maximum capacity; largest yearly activity
  through capacity factors, year split, availability and the activity limits).
- `gates/layers.py`: layers S (structure and connectivity), B (pairs of limits) and P (limits pushed along the
  chain in both directions; fuel balance per year and per time slice, emission limit by a duality bound, renewable
  target, reserve margin).
- `gates/standard.py`: layer R (registered values reached the compiled files, no emission penalty, rule outputs
  in [0, 1], identical history, registered BAU to policy differences, published targets only as minimums,
  provenance of every limit value, free unlimited sources).
- `gates/results.py`: layer X on extracted results (one-year jumps, loaded targets met, identical solved history).
- `gates/findings.py`, `gates/config.py`, `gates/run.py`: rows of `gate_results.csv` and `gate_summary.csv`, the
  tables the suite reads, and the command line (points, model and scenario filters, a data folder for copies,
  parallel models, exit code 1 on any FAIL).
- `config/gates/models.csv`: one row per `OSeMOSYS_Model.txt` (24): path, kind, A2 compiler, B1 runner, scenarios
  as each model's `B1_Scenario_Config.xlsx` activates them, base scenario, whether Stage 3 patches it, model file
  version.
- `config/gates/checks.csv`: one row per check (id, layer, class, what it proves, the constraints it rests on).
- `config/gates/thresholds.csv`: every tolerance, threshold, file name and parameter list the suite uses, one
  sentence per row.
- `test_gates.py`: for every check of the suite a tiny synthetic data file with a case that must be flagged and a
  case that must pass; runs in a few seconds without the models.

## Commit 2: stale compiled files and the compile-code fixes

- `DominicanRepublic/RD_AFOLU/A2_Compiler.py`: writes the base scenario's tables to `A2_Output_Params/BAU`, as
  JAM_AFOLU's compiler of the same code base does. Without it BAU was never regenerated and kept costs and emission
  penalties older than the workbooks.
- `DominicanRepublic/RD_AFOLU/A2_Output_Params/BAU/` and `B1_Output_Params/BAU/` (6 files each: CapitalCost,
  EmissionActivityRatio, EmissionsPenalty, FixedCost, ResidualCapacity, VariableCost): regenerated by the fixed
  compiler and the B1 runner; 231 penalties to 0, the costs #19 wrote (VariableCost IMPRIC 2030 743.63).
- `Ecuador/ECU_USCUSS/A2_Compiler.py`: writes the policy tables to every policy scenario that
  `B1_Scenario_Config.xlsx` activates, not only to `Other_Scenarios`; NDC and NDCCON were never regenerated.
- `Ecuador/ECU_USCUSS/A2_Output_Params/NDC/` and `NDCCON/` (19 files each) and `B1_Output_Params/NDC/` and `NDCCON/`
  (EmissionsPenalty, OutputActivityRatio): regenerated; 30 penalties to 0 per scenario, a missing non-motorised
  transport output row added, the folder's own scenario label.
- `Ecuador/ECU_IPPU/A2_Output_Params/NDCcond/` and `NDCincond/` (13 files each): the scenario label the compiler
  writes (tracked copies said BAU); values unchanged.
  Each file is listed in `stale_compiled.csv` with cells changed, an example and the cause.
