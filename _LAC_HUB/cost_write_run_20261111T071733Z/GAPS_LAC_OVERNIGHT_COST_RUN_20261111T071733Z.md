Judgement calls and their reasons, known-limitation candidates, what was left unchecked, incidents, and the groups left in their source currency year. Section 3 of the brief lists the decisions in force; this file records where the brief left a choice.

## 1. Judgement calls

### Setup and pipeline

1. **Interpreter.** On this machine `py` is python.org Python 3.12.0 with pandas 3.0.2, not Anaconda. The DR A2 compiler fails under pandas 3 (string dtype) and the Guatemala A2 compiler needs pandas 1.x (`DataFrame.append`, `ExcelWriter.save`). The pipeline scripts (A2, B1, Stages 0 to 3) were run with the Anaconda Python the brief names (3.12.4, pandas 2.2.2); my own scripts and the safe-save tests with `py -I`.
2. **Guatemala A2 compiler.** No environment on the machine has pandas 1.x. The compiler was run unchanged through `scripts/run_with_append_shim.py`, which restores `DataFrame.append`, `Series.append` and `ExcelWriter.save` with the pandas 1.5 logic. It reproduces the tracked BAU, NDCNEW and LTSNEW keyed with zero differences, so it is the canonical runner. No pipeline script was edited and no path fix was needed.
3. **Unittest gate A4.** `py -I -m unittest test_ao_cost_repair_manager -v` cannot import the module because `-I` drops the current folder from `sys.path`. The same four tests ran with `py -I -m unittest discover -s . -t . -p test_ao_cost_repair_manager.py -v`: 4 of 4 OK. Both logs are in the job folder.
4. **A2 scenario folders.** The compilers write BAU plus folders named after older scenarios (NDCincond and NDCcond for Costa Rica and the DR, NDCINC for Ecuador, NDP for Guatemala and Honduras; Jamaica writes LTSNEW itself). The tracked NDCNEW and LTSNEW folders are the existing folders with one such folder's produced files copied over them; the Scenario column keeps the compiler's label. The source folder was chosen per country by the fewest keyed differences: Costa Rica BAU, DR NDCcond, Ecuador BAU, Guatemala NDP, Honduras NDP, Jamaica LTSNEW. Files the compiler does not write (header-only files) stay as they are. Output folders the compiler writes but that are not tracked were created empty for the run and removed after.
5. **A2 side files.** The compilers also rewrite `A1_Outputs/*_COMPLETED.xlsx`, the fleet pickles and `A2_Structure_Lists.xlsx` (Guatemala also writes an untracked `A2_Extra_Inputs/A-Xtra_Projections_COMPLETED.csv`). They were restored with `git checkout` after every run so the diff stays inside the scope of F1; nothing downstream in this job reads them.
6. **Costa Rica LTSOPT.** `B1_Scenario_Config.xlsx` activates a fourth scenario, LTSOPT, with no `A2_Output_Params/LTSOPT`, so the Costa Rica B1 runner stops at once. Without editing the config, a temporary `A2_Output_Params/LTSOPT` (copy of LTSNEW) and an empty `B1_Output_Params/LTSOPT` were created for each B1 run and removed afterwards together with `Executables/LTSOPT_0`. BAU, NDCNEW and LTSNEW then reproduce exactly.
7. **Solve status and objective of B1.** B1 deletes the solver output after parsing it. To record status and objective without editing B1, `scripts/glpsol_wrap/glpsol.bat` was put first on PATH for the B1 runs; it calls the real `glpsol.exe` with the same arguments, logs the Status and Objective lines of the `-o` file and passes the exit code through. For Stages 0 and 3 the batch files call `glpsol.exe` directly and status and objective are read from the headers of the kept `-o` files (`scripts/solve_headers.py`).
8. **SelectedResults.csv.** B1 writes it in the model folder (last writer wins). Untracked copies were deleted; Ecuador's tracked copy was restored with `git checkout`.
9. **Line endings in the job folder.** Every text file in the job folder (including the baseline copies of pipeline outputs and data files) was normalised to LF and trailing blanks removed before committing, for the repository diff check. Keys and values are unchanged. Pipeline outputs in the model and stage folders keep the CRLF line endings of the files they replace.

### Write set (Phase C)

10. **D3, Costa Rica.** The source job states the workbook convention: the 2021 column in 2021 USD and 2022 to 2050 in 2022 USD (LAC_COST_SRC_CR REPORT line 58 and GAPS item 11). Costa Rica groups were converted per column (2021 by CPI-U 2024/2021, 2022 to 2050 by CPI-U 2024/2022); one factor per group would leave the 2021 column in different units from the rest.
11. **D3, per row.** The currency year was taken per row: a year written next to the proposed number, then the last year written in the clause the value comes from (the "newer edition" clause for upgrade rows, the text before it otherwise), then one year stated across the row's source entries in `sources.csv`. A group can therefore mix converted and left rows (Honduras keep rows 2018 to 2023 from PIEG 2024-2033 Tabla 7, upgrade rows 2024 to 2050 from PIEG 2026-2035 in 2024 USD).
12. **D3 overrides**, each written into `currency_conversion.csv`: Guatemala PPHDAM FixedCost left (the value 50 USD/kW-yr is from PEIG 2026-2050, whose entry says the currency year is not stated; IRENA 2022 is only a range check); Guatemala PPPVDS takes PPPVD's year for each column (a unitless ATB ratio times the PPPVD value); Jamaica PPPVDS and PPWNDONS CapitalCost and FixedCost left (sum of a PPPVD or PPWNDON part and an IRP battery part in different currency years); Jamaica PPBGS and PPBIM VariableCost: keep rows from IRENA in 2022 (2022 USD, converted), upgrade rows from IRENA in 2025 (2025 USD, left).
13. **D3, years after 2024.** The rule covers years before 2024, so values stated in 2025 USD were left (Jamaica PPGEO FixedCost, the IRENA 2025 rows). Jamaica PPNGS CapitalCost (January 2010 prices) was left: no CPI-U 2010 is in any `constants.csv`.
14. **D8, reading of "written values".** Read as the row as it stands after the write: written cells plus cells left as they are. A2's Flat mode copies the first year column to every year, so a Flat row with new values written only from 2024 (Honduras PPHDAM FixedCost: 47.06 for 2018 to 2023, 37.93 from 2024) varies by year and is switched; reading only the written cells would leave it Flat and the written values unused.
15. **D8 fill.** 14 rows switched from Flat to User defined had empty year cells that were not written because their proposals are "keep" (Honduras PPHDAM, PPHROR, PPGEO, PPGTDSL, PPICEDSL, PPFOI and PPGTGLP FixedCost or VariableCost, 2019 to 2023; Ecuador PPPVT CapitalCost 2049 and 2050 and PPWNDON CapitalCost 2026). Flat filled them from the first column; under User defined they would compile as missing (zero cost). The 63 empty cells received their keep proposal value, which equals what Flat produced after A2's 4-decimal rounding, so those years compile as before. This writes keep rows that D3 did not change, against the letter of C1, to honour D8 without changing the model in those years.
16. **D7 scope.** From the review pack REPORT ("Gas conversion"): the F5 gas sentence sits on 105 Jamaica DIST_NGS rows and 81 DR DIST_NGS projected rows whose values were not divided by 0.9 (LNG import CIF per tonne over the IPCC net calorific value is already net). It was removed from the 62 of those rows the base models write (STEPS); those rows keep no ASSUMPTION sentence.
17. **D4.** EXTT_CRU and PRO_COA VariableCost take the DIST_CRU and DIST_COA path as it stands after the write: the written value where a cell is written, the workbook value where the DIST cell is "keep" (DIST_CRU 2019, DIST_COA 2030).
18. **D2.** R was recomputed from the three ICE PEG 2024-2040 Tabla 10.9 plants: (5986 x 623 + 6317 x 162 + 5910 x 209) / 994 = 6,023.9658 USD/kW (Dec-2023 USD), times 313.689/304.702 = 6,201.6390 USD/kW. Every year of the regional path was multiplied by 6,201.6390/5,100 = 1.2160076.
19. **C4(4).** The brief speaks of "the 20 other A-O workbooks"; no list of 20 was found. Every other tracked `A-O_*.xlsx` (469 files, 41 of them `A-O_Parametrization.xlsx`) was checked and found byte-identical to the base commit.

## 2. Known-limitation candidates

- `Jamaica/JAM_ENERGY/A1_Outputs/A-O_Parametrization.xlsx` TotalAnnualMinCapacityInvestment of PPPVT and PPWNDON: edited on 12 May (`JAM_AO_BAU_edits.xlsx`, BAU keeps signed PPAs only) after the 27 January data files that the 16 May Stage 3 used.
- `Guatemala/GUA_ENERGY/A1_Outputs/A-O_Parametrization.xlsx` Primary Techs I284:J284: DIST_FLEXFUEL VariableCost 2018 and 2019 are formulas `=I14+(I14*0.8)` on DIST_GSL VariableCost, so they moved with the written gasoline price (47.11 to 45.31, 41.05 to 40.11).
- `Honduras/HON_ENERGY/A1_Outputs/A-O_Parametrization.xlsx` Secondary Techs I27:K27: PPBGS CapitalCost 2018 to 2020 are formulas `=I17*(5053/5391)` on PPBIM CapitalCost, so they moved with the regional PPBIM value (5053 to 1813.8 USD/kW); from 2021 PPBGS is a plain 5,390 USD/kW, which no proposal covers.
- `DominicanRepublic/RD_ENERGY/A1_Outputs/A-O_Parametrization.xlsx` Secondary Techs J232: Excel rewrote the formula text on save (the space after "=" removed); same value.
- `Costa Rica/CR_ENERGY/t1_confection/B1_Scenario_Config.xlsx`: LTSOPT is activated without an A2 folder, so the base B1 runner cannot run without a temporary LTSOPT input.
- `CostaRica/CR_ENERGY/t1_confection/B1_Scenario_Config.xlsx`, sheet Efficiency: SpecifiedAnnualDemand of E5INDCOA is set by "Exact" values for BAU, NDCNEW, LTSNEW and LTSOPT (2021 = 0.675, 2022 = 0.00667), so B1 overrides D9: the workbook and A2 carry 0.00667 for 2021, while B1_Output_Params, the data files and every solve still use 0.675. Editing the config is outside the brief.
- Phase D gate D2: 324 values outside the allowed list, all from the two formula chains above, in A2, B1 and the data files of all three scenarios: Guatemala DIST_FLEXFUEL VariableCost 2018 to 2050 (a "Percent growth of incomplete years" row whose 2018 and 2019 cells are formulas on DIST_GSL, so the whole path moves about 2 percent: 47.11 to 45.31 in 2018, 73.58 to 71.89 in 2050) and Honduras PPBGS CapitalCost 2018 to 2020 (5,053 to 1,813.8). "Fixing the write" would mean writing unsourced constants over the workbook's formulas or not writing sourced cells, so they were recorded and left.
- Ecuador objective: the Ecuador fuel, extraction and import VariableCost rows were placeholders of 1 USD/GJ (Flat) before the write. The proposals fill them with sourced prices (on average DIST_DSL 18.7, DIST_GSL 20.3, EXTT_CRU 17.3, DIST_CRU 11.9 and IMPELE 68.8 USD/GJ), so the Ecuador objective rises about eighteen-fold (Stage 3 BAU 107,054 to 1,933,690). Not tuned.
- Guatemala PPPVT before 2025 (E3, rechecked by values): new capacity 0.386 GW in 2018 and 0.280 GW in 2022 in NDCNEW and LTSNEW, 0.667 GW in total as on 16 May, none in BAU, against a residual capacity of 0.08 GW. The cause is in the B1 inputs: the NDCNEW and LTSNEW TotalTechnologyAnnualActivityLowerLimit of PPPVT for 2018 to 2024 (3.81 PJ in 2018, 6.46 PJ in 2022) is five to ten times the BAU value (0.54 and 0.63 PJ), and 3.81 PJ at the 2018 capacity factor 0.2607 needs 0.466 GW. Stage 3 only patches 2025 onward.

Whether they also failed on 16 May is not recorded.

- Line endings: the A2, B1 and Stage 0 CSV files are CRLF (as the tracked files they replace), so plain `git diff --check` reports a CR at the end of every changed line of those files; `git -c core.whitespace=cr-at-eol diff --check` is clean.
- The A2 compilers write scenario folders named NDCincond, NDCcond, NDP and LTS; NDCNEW and LTSNEW are made by copying (Phase B step), which no script in the repository does.

## 4. Incidents

- Stage 3 test T4 and the Stage 2 soft tests failed (section 2); the pipeline continued as the brief requires.

- The first Costa Rica B1 attempt stopped at once on the missing LTSOPT folder (logged in `baseline/CostaRica/B1/cand0_anaconda_no_LTSOPT_input`).
- The second Costa Rica B1 attempt solved all four scenarios OPTIMAL but the solve wrapper could not open its log (a relative path), returned exit 1 after each solve and B1 stopped before parsing; the 783 MB solver outputs of that failed run were deleted and the run repeated with an absolute log path.
- Stage 0, attempt 1: `cmd /c stage0_run_all.bat` was refused (`not recognized`) because this session sets `NoDefaultCurrentDirectoryInExePath=1`, so `cmd` does not look in the current folder; the later Stage 0 steps then ran on no outputs. The batch files were called by full path from attempt 2 on (logs in `stage_logs/attempt1_stage0_bat_not_found`).
- Stage 0, attempt 2: with the `glpsol.bat` wrapper on PATH, the batch file handed control to the wrapper after the first solve (a batch calling another batch without CALL does not return), so only Costa Rica BAU_S0 was solved. The wrapper was removed from the stage runs and Stage 0 was run again from the start (logs in `stage_logs/attempt2_wrapper_ended_batch`).
- The first A2 comparison pass keyed folders on the Scenario label and read folders a failed compiler had not rewritten; its listings were discarded and the driver corrected (baseline/README.txt).
