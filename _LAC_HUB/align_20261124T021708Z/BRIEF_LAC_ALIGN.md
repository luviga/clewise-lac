## 2. The standard

- The models run only on externally sourced values, values a rule computes every run from sourced inputs, and labelled ASSUMPTIONs. Every derived value names its inputs and formula. Nothing is stored from an earlier run.
- Cite only external, retrievable sources: a URL, a DOI or a public repository permalink with commit hash. Never cite internal files (workbooks, sheets, cells, markdown, handovers, CSVs we built, local paths, CLG reports, CLG Read the Docs pages, CLG GitHub models). Those are leads: follow them to the external document they cite, download it, open it, and cite that.
- Every source enters a model only after you downloaded it, opened it and found the value in it. Keep the copy under the job folder's `downloads/` (gitignored) and record its URL, retrieval date, page or table, and SHA-256 in `sources.csv`.
- ASSUMPTION sentences follow these rules. Each states the value with unit and coverage, the reason in plain words with every constant stated, a check against a public document where one exists (how far the value sits from it), and a range when the value matters to results. One to three sentences, present tense. Never write about our process or history (agents, jobs, hubs, pull requests, earlier runs, "kept as used", "retained", "previously"), internal files (workbook, sheet, cell, CSV, path), owner rulings as the reason, or what could not be found ("not found", "no public source", "unknown origin", "provisional").
- No value of the system lives in a script. Every number and element name goes in a table: costs, lives and distances in the A-O workbooks; targets in `inputs/scenarios/scenario_values.csv` and the existing transport and power inputs; rule numbers in `config/scenarios/rules/stage_controller.csv` and `config/scenarios/technology_types.csv`; run settings in `config/execution/Config_MOMF_T1_AB.yaml`. Code holds rules only.
- Model files hold structure only. No `OSeMOSYS_Model.txt` (24 copies) changes in this job. A limit, a cap or a switch goes in through a parameter in the data.
- Rules in force (Luis, 21 November): no input differs between BAU and a policy scenario unless it is a policy measure; history (years up to 2024) is identical in every scenario; the NDC scenario uses published values, conditional commitments included, held after the last stated year; every published value is checked three times and compared in one unit system; LTS equals NDC through 2035; scenario names are BAU, NDC, LTS; through 2035 the NDC in force wins, after 2035 the long-term document.
- Writing: plain English, no em dashes, in every file you write. Commits and the pull request carry no "Co-Authored-By" line and no "Generated with Claude Code" line. Check `git log -1 --format=%B` after each commit and amend if such a line appears.
